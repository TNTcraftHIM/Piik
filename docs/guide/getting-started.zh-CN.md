# 第一次用 Piik

[English](./getting-started.md) · 简体中文 · [回到 Piik](../../README.zh-CN.md)

Piik 支持一位房主分享屏幕，最多 20 位受邀观众通过浏览器观看。
本指南介绍加入房间、使用在线版、使用 Piik App，以及通过已有站点分享的方法。

[加入房间](#加入朋友的房间) · [在线版](#使用在线版) ·
[Piik App](#用-piik-app-分享) · [已有站点](#使用已有站点分享) · [问题排查](#遇到问题了)

观众只需要浏览器和邀请链接。
分享画面推荐下载 Piik App，选择 **公网邀请**。
想免安装，可以打开[在线版](https://demo.piik.tv)，直接在浏览器里创建房间并分享。

## 加入朋友的房间

1. 用电脑或手机浏览器打开朋友发来的邀请链接。
2. 等待画面出现。如果浏览器没有自动播放，点击 **播放**。
3. 将鼠标移到画面上，或轻点画面，显示播放控制栏。

播放控制栏只改变你自己看到的画面和听到的声音。
电脑上单击画面可暂停或继续，双击可进入或退出全屏（浏览器支持时）。
手机上轻点画面唤出控制栏，再使用其中的按钮。Safari 的视频全屏可能使用系统播控。

<details>
<summary>播放按钮分别做什么？</summary>

| 按钮 | 作用 |
| --- | --- |
| **剧场模式** | 在浏览器标签页内展开画面。 |
| **全屏观看** | 让画面铺满屏幕。 |
| **悬浮小窗** | 浏览器支持时，把视频放进独立小窗。 |
| **音量** | 支持增强时最高 200%，否则最高 100%；声音失真时调低一些。 |

</details>

只有四位房间号时，打开同一个 Piik 站点，选择 **加入房间**。
你可能需要站点口令和房间密码。能否通过房间号加入由房主决定；
无法加入时，请朋友发邀请链接。

旧链接失效了，就请房主重新发一份当前邀请。
App 的本地房间和临时公网邀请会随本次 App 退出而结束。

## 使用在线版

1. 在支持屏幕共享的电脑浏览器中打开 [demo.piik.tv](https://demo.piik.tv)。
2. 点击 **开始分享**，选择屏幕、窗口或标签页；如需声音且浏览器提供该选项，启用音频。
3. 确认预览后，点击 **复制邀请链接**，用另一台设备打开，或发送给朋友。
4. 分享结束后，点击 **停止分享**。

在线版由项目提供，画面仅通过设备间直连（P2P）传输。
在受限网络下，可能出现页面能打开、画面无法连接的情况。

## 用 Piik App 分享

1. 从 [GitHub Releases](https://github.com/TNTcraftHIM/Piik/releases) 或
   [Gitee 镜像](https://gitee.com/TNTcraftHIM/Piik/releases)下载以 **`piik-app`** 开头、
   对应平台的压缩包，完整解压并保留目录结构。
2. Windows 打开 `piik-app.exe`，macOS 打开 `Piik App.app`，Linux 运行 `./piik-app`。
   启动页会在系统浏览器里打开。
3. 邀请不在同一局域网的朋友时，选择 **公网邀请**，再点击 **进入 Piik**。
   其他模式的用途见下表。
4. 点击 **开始分享**，按可用选项选择 **浏览器**、**程序 / 窗口** 或 **屏幕**，
   然后选定要分享的画面与声音。
5. 复制房间邀请发给朋友。分享期间保持 App 和分享标签页打开。

| 文件名包含 | 适用平台 |
| --- | --- |
| `windows-amd64` | Windows x64 |
| `darwin-arm64` | Apple 芯片；原生采集需 macOS 13 及以上 |
| `linux-amd64` | Linux x64 |

目前主要测试 Windows 版 Piik App 和浏览器分享。macOS 和 Linux 版 Piik App 尚未经过实机测试，
欢迎有设备的朋友试用并[反馈问题](https://github.com/TNTcraftHIM/Piik/issues)。
Linux 原生采集还需要[系统组件](../../native/capture/linux/README.md)。
程序包与启动参数的细节见 [App 指南](../../cmd/piik-app/README.zh-CN.md)。

### 选择 App 模式

| 模式 | 什么时候用 | 需要知道 |
| --- | --- | --- |
| **本地房间** | 朋友和你在同一个局域网。 | 出现多个「局域网邀请地址」时，选择与朋友同一网络的网卡和 IP。对方需要能连接到你的电脑，可以设置本地站点口令。 |
| **公网邀请** | 朋友在别处，想临时发个邀请。 | 需要互联网连接；公网地址只在本次 App 运行期间有效。 |
| **连接站点** | 你们已经有一个 Piik 站点。 | 输入站点地址，在原有分享页面使用 App 的采集能力。 |

使用 **连接站点** 时，填写完整地址，例如 `https://demo.piik.tv`；如果站点有访问口令，
也一并填写，然后点击 **进入 Piik**。通过 App 打开过一次后，同一浏览器会记住这个入口。
保持 App 运行并使用该站点配置，之后就能直接访问网址。点击 **开始分享**，
在选择器里选 **程序 / 窗口** 或 **屏幕**，即可使用 App 采集。
浏览器询问本地网络权限时，请允许访问。换浏览器、使用无痕窗口或清除站点数据后，
需要重新从 App 进入一次；换用其他站点时，先在 App 中更新地址。

**网页能打开，不代表视频一定能连通。** 公网邀请为房间提供临时网页地址，
画面和声音仍靠参与者之间的连接传输。此模式没有媒体服务器兜底，
临时地址也不保证持续可用。所有模式都需要可用的 UDP 媒体路径。
具体连接方式见 [App 指南](../../cmd/piik-app/README.zh-CN.md#运行模式)。

## 使用已有站点分享

需要先有一个运行 Piik Server 的 HTTPS 站点，可以使用朋友或管理员提供的地址。
也可以使用项目提供的[在线版](#使用在线版)或 [Piik App](#用-piik-app-分享)。
自建站点属于进阶操作，服务器、HTTPS 和网络端口的配置步骤见[部署指南](../operations/self-hosting.zh-CN.md)。

1. 在电脑上打开 Piik 站点。如果站点设置了口令，先输入口令。
2. 点击 **开始分享**，在浏览器弹窗里选择屏幕、窗口或标签页；
   如需声音且浏览器提供该选项，启用音频。
3. 确认预览画面后，点击 **复制邀请链接** 发给朋友。
4. 保持分享标签页打开。需要时使用 **暂停分享**、**切换来源** 或 **停止分享**。

浏览器屏幕采集需要 HTTPS 站点或 `localhost`。
弹窗里有哪些画面和声音可选，取决于浏览器与操作系统。
拿到邀请链接的人可以进入这个房间，请把它发给你想邀请的人。

## 遇到问题了

| 你遇到的情况 | 可以先试什么 |
| --- | --- |
| 有画面，没声音 | 先取消视频静音。房主应选择支持分享声音的来源；如果开始时关闭了声音，请停止后重新开始并打开声音。通过 App 采集窗口或屏幕时，切换来源会保留原来的声音设置。 |
| 没有屏幕选择弹窗 | 按系统提示允许浏览器或 App 录制屏幕。浏览器采集需要 HTTPS 或 `localhost`，请在电脑上尝试分享。 |
| App 的窗口或屏幕列表为空 | 保持 App 运行，从 App 重新打开分享页面；浏览器询问本地网络权限时允许访问，再刷新来源列表。也可以选 **浏览器** → **浏览器选择器**，使用浏览器采集。仍然失败时，按下方说明收集诊断报告。 |
| App 启动失败 | 先查看页面和终端中的具体原因。重新打开 App，在主题按钮后的芯片图标开启「诊断启动」再重试。启动失败时会自动导出报告，保存位置见终端。 |
| 本地邀请打不开 | 确认两台设备在同一网络且可以互相访问。访客 Wi-Fi 或防火墙规则可能阻止本地连接。 |
| 网页能打开，画面连不上 | **重新连接** 按钮可用时先点击，否则刷新观看页。仍然失败时，查看 [画面连接排查](#画面连接不上)。 |
| 休眠或挂起后分享中断 | 唤醒设备，回到分享标签页，必要时重新开始分享。浏览器或系统挂起可能中断采集和播放。 |

反馈问题时，请附上版本、系统与浏览器、预期结果和复现步骤。
[诊断与导出](../standards/configuration.md#diagnostics)
说明如何收集本地报告，以及分享前需要检查哪些内容。

### 画面连接不上

**没有可用的媒体线路** 表示 Piik 还没有找到能把画面送到你设备上的连接。
网页和媒体使用不同的连接，所以可能出现网页能打开、画面却连不上的情况。

NAT（网络地址转换）让多台设备共用一个上网地址。不同路由器和运营商对地址转换、
外部数据进入的规则不同，有些组合会让设备难以直连。防火墙和浏览器策略也可能阻止媒体连接，
仅凭这条提示还不能确定具体原因。

可以依次尝试，画面恢复后就不必继续：

1. **重新尝试观看连接。** 如果 **重新连接** 可用，先点击；按钮不可用或没有效果时，
   刷新观看页或重新打开邀请链接。每次等连接尝试结束，重试一两次即可；反复刷新无法解除网络限制。
2. **换个网络测试。** 例如试用手机热点。如果使用了 VPN、代理或限制 WebRTC 的扩展，
   检查其 UDP 策略，受管理的网络请联系管理员。详见 [浏览器连接设置](../../cmd/piik-app/README.zh-CN.md#chromium-webrtc-连接)。
3. **开启可用的 IPv6。** 先确认宽带、路由器和设备都支持。连接双方都有可用 IPv6 时，
   Piik 可以多尝试一条直连路径；它仍受防火墙规则约束，同时保留 IPv4 即可。
4. **检查自己管理的路由器。** 在可信家庭网络中，路由器支持的 UPnP、PCP 或 NAT-PMP
   可以让 App 的原生媒体连接申请端口映射；纯浏览器采集不会申请这些映射。
   如果光猫和路由器都在做 NAT，可按对应型号的桥接或 AP 模式说明减少一层。
   运营商共享公网地址（CGNAT）位于路由器上游，需要向运营商咨询公网 IPv4 或 IPv6 服务。
   修改路由器工作模式前，先备份配置。
5. **请另一网络的朋友加入。** 如果对方能正常看到画面，且有余力转发，Piik 可能经由这位观众
   把画面送到你这里。线路由 Piik 自动选择，能否帮上忙取决于这些连接是否可用。
6. **使用有媒体兜底的站点。** 管理员需要先启用 SFU 转发，房主在分享前关闭 **隐私模式**。
   公开站点 `demo.piik.tv` 和 App 的 **公网邀请** 模式均没有 SFU 兜底。
   有服务器的用户也可以按 [部署指南](../operations/self-hosting.zh-CN.md#可选启用媒体兜底) 配置，属于进阶操作。
   目前 P2P 和 SFU 媒体都使用 UDP；网络完全禁止 UDP 时，仍需换网络或由管理员放行。

不同型号的路由器菜单会有差异，可参考厂商的
[IPv6 条件说明](https://support.google.com/googlehome/answer/6361450?hl=zh-Hans)、
[UPnP 说明](https://support.google.com/googlehome/answer/6274337?hl=zh-Hans) 和
[双重 NAT 调整示例](https://www.tp-link.com/us/support/faq/3113/)（英文）。
想了解连接机制，可以阅读 [WebRTC 官方说明](https://webrtc.org/getting-started/peer-connections)（英文）。

仍然失败时，收集出现问题的观众端与房主端同一次尝试的
[诊断报告](../standards/configuration.md#diagnostics)，反馈时附上发生时间、Piik 版本和所用网络类型。

想为朋友搭一个站点？从 [部署指南](../operations/self-hosting.zh-CN.md) 开始。
其他内容可在 [文档导航](../README.md) 找到。
