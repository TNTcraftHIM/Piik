### 进不去朋友的房间

请房主发来当前邀请，在浏览器中打开完整链接。

- **浏览器提示无法访问。** 如果房主发的是[本地邀请](#本地邀请打不开)，双方需要在能互相访问的网络上。异地朋友可以请房主发 **公网邀请**。公网地址显示 1033 时，请房主[检查邀请状态](#公网邀请创建失败或出现-1033)。
- **标签页有标题，页面一直空白。** 在另一款浏览器里打开同一链接。如果仍然空白，请朋友也试一次，告诉房主哪些设备能打开。
- **已经能看到房间，电视里没有画面。** 请房主看一眼自己的预览，再按[画面连接检查](#画面连接不上)操作。

<span id="app-not-ready"></span>

### App 启动失败或没有打开网页

1. 查看启动页面和终端中的原因。App 仍在运行时，可复制显示的地址，在浏览器中打开。
2. 本地模式列出多个地址时，选择朋友能访问的网卡和 IP，见[本地邀请排查](#本地邀请打不开)。
3. 仍然失败时，开启 **诊断启动** 后重试，保留完整错误和 [App 报告](#反馈问题)。

### 安卓 APK 无法安装

按 [App 安装步骤](./getting-started.zh-CN.md#用-piik-app-分享)下载 APK。
安卓提示时，允许本次使用的浏览器或文件管理器安装下载的 APK。

如果安卓提示软件包冲突或签名不一致，先确认是否装过 Piik 测试版。卸载会清除 App 设置，包括已授权站点和收藏的启动站点。浏览器设置会保留。若装过测试版，请卸载它，再安装正式 APK。测试版与正式版签名不同，之后的正式更新可以覆盖安装。

### macOS 提示已损坏或无法验证开发者

当前 Mac 版本未进行 Developer ID 签名和 Apple 公证。首次打开时，先校验下载文件，再为这个 App 放行：

若 macOS 提示恶意软件、「会损坏你的电脑」，或自动将 App 移到废纸篓，
请[保留完整提示和下载链接反馈](#反馈问题)，不要使用下方的隔离标记命令。

1. 从项目 Releases 下载对应的 Mac ZIP，核对同一版本公布的 SHA-256。
   在终端运行 `shasum -a256 ~/Downloads/piik-app-darwin-arm64.zip`；
   Intel Mac 将文件名中的 `arm64` 换为 `amd64`。校验不一致时应重新下载，不要绕过警告。
2. 把完整的 `Piik App.app` 移到「应用程序」，尝试打开后，在
   **系统设置 → 隐私与安全性 → 仍要打开** 中确认。
   具体步骤见 [Apple 首次打开说明](https://support.apple.com/zh-cn/102445)。
3. 如果没有「仍要打开」，且已确认官方 ZIP 的校验值一致，可在终端仅移除这个 App
   的下载隔离标记，再重新打开：

   ```sh
   xattr -dr com.apple.quarantine "/Applications/Piik App.app"
   ```

保留在其他位置时，换成 App 的实际路径。保持系统整体安全检查开启。

### 公网邀请创建失败或出现 1033

1. 请房主唤醒电脑，保持 App 运行，重新发送当前邀请。App 重启后临时地址可能改变。[错误 1033](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1033/) 表示公网邀请的隧道已断开。
2. 房主确认 App 已完整解压，再用 **诊断启动** 重试。看到 `exit status 1` 或 `public invitation service exited before connecting` 时，保留退出码后面的具体错误。
3. 用手机热点再试。如果热点可用，请网络管理员按下表检查原网络的代理、DNS 和防火墙。

<details>
<summary>进阶：隧道错误、代理与 7844 端口</summary>

使用代理时，请确认它实际覆盖 `cloudflared` 进程。仅开启浏览器代理或设置
`HTTP_PROXY`／`HTTPS_PROXY`，不会让当前随包的隧道程序自动走代理。

错误详情可以帮助区分失败的环节：

| 错误中出现 | 检查什么 |
| --- | --- |
| `failed to request quick Tunnel`、`api.trycloudflare.com` | 临时地址申请失败。查看后面的具体原因：域名解析错误检查 DNS；连接超时检查 HTTPS 出站连接、代理或服务状态。 |
| QUIC 超时、`dial tcp ...:7844` 或 `TLS handshake with edge` | 到 Cloudflare 隧道节点的连接失败。检查 `cloudflared` 的出站规则，包括代理或游戏加速器是否影响该连接。 |

Piik 在 QUIC（UDP）失败后会尝试 HTTP/2（TCP），请允许两者使用出站端口 `7844`。
具体要求见 [Cloudflare 连接排查](https://developers.cloudflare.com/tunnel/troubleshooting/)（英文），
无需在路由器上开放入站端口。

</details>

**暂时绕过公网邀请：** 保持 App 运行，打开[在线版](https://demo.piik.tv)或其他可访问站点，
[授权 App 采集](./getting-started.zh-CN.md#通过已有站点使用-app)，再发送新站点的房间邀请。
在线版无需站点口令，媒体使用 P2P；需要服务器转发时，选择启用 SFU 的站点。
网页能打开但画面连不上时，转到[画面连接排查](#画面连接不上)。
如果打不开的是自建站点而非 App 的临时地址，请联系该站点管理员检查服务。

### 本地邀请打不开

1. 请房主保持 App 运行，在 **本地房间** 选择朋友能访问的网卡地址，复制完整邀请。双方应在可互访的局域网或同一虚拟局域网。访客 Wi-Fi 可能隔离设备。
2. 如果朋友无法使用同一网络，请房主改发当前的 **公网邀请**。

<details>
<summary>房主进阶排查 · 防火墙和端口</summary>

1. Windows 房主打开 **Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙**，给当前 `piik-app.exe` 放行正在使用的网络类型。换过解压目录时，更新旧规则的路径。虚拟网卡可能属于 **公用网络**，高级规则可限定网卡和网段。[Microsoft 防火墙说明](https://support.microsoft.com/zh-cn/windows/security/firewall/risks-of-allowing-apps-through-windows-firewall)
2. 若 App 提示 **本地端口不可用**，关闭占用端口的旧 Piik 实例。其他程序需要该端口时，用 `--port 9876` 启动 Piik，发送新邀请。网页和本地 STUN 端口都需可用。

</details>

网页打开后仍看不到画面，请转到[画面连接排查](#画面连接不上)。

<details>
<summary>可选 · 虚拟局域网邀请只显示标题时，检查页面请求和 MTU</summary>

如果标签页显示 **Piik**，但网页一直空白或加载中，请打开浏览器的 **开发者工具 → 网络**，
重新加载邀请，查看网页文档和主 JavaScript 请求。

- 如果请求一直等待或超时，有条件时在同一个实体局域网访问同一房主。如果只在虚拟局域网中卡住，
  请检查虚拟网络路径，包括该路径能否传输较大的数据包。
- 如果 JavaScript 返回 `404`，请用隐私窗口重新打开当前邀请。若仍有问题，请告诉房主正在使用的版本和脚本返回的 `404`。
- 如果 JavaScript 下载完成后页面仍卡住，请在浏览器的 **控制台** 查看是否有 JavaScript 错误。

如果网页文档等小响应能收到，但完整脚本下载超时，隧道可能丢弃了较大的数据包。
新建连接也可能在 TLS 握手阶段超时，此时浏览器还未收到 HTTP 响应。可在虚拟局域网内做前后对照：

1. 确认两台设备上承载该邀请流量的虚拟网卡，记录当前 MTU（最大传输单元），用新连接测试同一个邀请。
2. 使用服务商支持的设置恢复路径 MTU 反馈（例如 ICMP 数据包过大消息），或将两端虚拟网卡的 MTU
   调整到已知隧道路径支持的值。由服务商管理这些设置时，请联系其支持团队。
3. 再用新连接检查网页文档和完整脚本能否加载。如果没有改善，恢复原设置。

</details>

#### 安卓打不开虚拟局域网邀请

1. 在安卓设置中搜索 **VPN**，查看当前连接的是哪个应用。如果是其他 VPN，或占用 VPN
   连接的代理、广告过滤应用，先断开它，再连接组网工具。
2. 如果组网工具有按应用分流的设置，确认浏览器会走组网 VPN。如果浏览器在排除名单里，把它移除。
3. 重新连接同一个虚拟局域网，直接用浏览器打开完整邀请。如果网页时开时不开，
   换网络或重连组网工具后，等组网恢复再刷新原来的完整邀请。
   如果看到证书提示，先[和房主核对本地证书](#本地-https-证书提示)。

如果已经进房，也看到有人正在分享，但画面连不上，检查组网工具能否在设备之间传输
UDP。也可以切换 Wi-Fi 或移动数据，等组网重新连上后再进房试一次。
[检查浏览器的 WebRTC 设置](./network.zh-CN.md#浏览器限制了-webrtc) ·
[「没有可用的媒体线路」](./no-media-route.zh-CN.md)

<details>
<summary>进阶 · 安卓 VPN 的连接拦截设置</summary>

在 VPN 的设置中，**屏蔽未使用 VPN 的所有连接**会拦截走 VPN 之外的流量，例如被排除的应用或绕过 VPN 的局域网流量。
如果组网工具确认你要测试的连接绕过 VPN，可以在个人设备上暂时关闭此项做一次对照，测完再恢复。
[Android VPN 设置说明](https://developer.android.com/develop/connectivity/vpn?hl=zh-cn#blocked-connections)

</details>

### 本地 HTTPS 证书提示

如果是本地邀请，通过平时联系房主的渠道核对地址，再按下方步骤比对证书指纹。也可以请房主改发当前的 **公网邀请**。如果公网地址也有警告，请联系站点管理员，待修复后再打开。

<details>
<summary>进阶 · 与房主核对预期的本地证书</summary>

Piik App 的 **本地房间**，以及启用 `TLS_SELF_SIGNED=true` 的服务端，会自行生成本地证书。
它没有经过公共证书机构签发，因此浏览器会先显示证书警告。

1. 确认网址与房主准备分享的地址一致。
2. 打开警告页的证书详情，将 **SHA-256 指纹** 与房主 App 终端中的 **本地证书 · SHA-256**，
   或服务端启动时的 **HTTPS certificate** 信息对照。异地使用时，可通过平时信任的聊天渠道向房主核对。
3. 指纹一致后，使用浏览器提供的 **高级 → 继续访问**；进入页面后，再正常允许麦克风或申请远控。

重启 App／服务端会更换临时证书，新指纹需要重新确认。App 不保存证书文件，也不安装系统受信任证书。
不要全局关闭浏览器的安全检查。如果浏览器不允许接受例外，请改用该设备已信任证书的 HTTPS 站点；
管理员可参阅 [HTTPS 部署说明](../operations/self-hosting.zh-CN.md#2-配置-https)。

以上只适用于预期中的本地自签名证书；普通公网 HTTPS 站点突然出现证书警告时，应让管理员排查原因。

</details>

### 房间号无法使用

请房主从当前房间复制完整邀请，观众直接打开链接。房间号只在创建它的站点有效。如果房主也打不开旧房间，可能是空房间已过期。请房主新建房间并发送新邀请。[加入朋友的房间](./getting-started.zh-CN.md#加入朋友的房间)

站点房间号已用满时，稍后重试或使用其他 Piik 站点。管理员可配置
[空房间回收](../operations/self-hosting.zh-CN.md#1-配置并启动-piik)以收回闲置号码。

### 创建房间返回 403

向站点管理员确认开房地址。仍显示 403 时，把站点地址和错误文字发给管理员。

<details>
<summary>站点管理员 · 检查允许的地址</summary>

浏览器访问的网址不在服务端允许的范围内时，页面可能正常打开，但创建房间会被拒绝。
站点管理员可以按以下步骤检查：

1. 将 `PUBLIC_BASE_URL` 设为浏览器访问的站点地址，包含协议和非默认端口，不带路径。
2. `ALLOWED_ORIGINS` 不设置或留空时使用上述地址；需要多个地址时，用英文逗号列出全部
   可信地址。复制过配置示例的话，检查这里是否仍残留 `http://localhost:8787`。
3. 重启 Piik；使用 Compose 时运行 `docker compose up -d` 重建容器。刷新网页后重试。

配置正确但响应仍是 `Origin not allowed` 时，检查反向代理是否保留浏览器的 `Origin`
请求头。如果 403 来自代理或 WAF 本身，则应查看对应日志，不要通过关闭来源校验来绕过。
配置方法见 [Server 部署指南](../operations/self-hosting.zh-CN.md)。

</details>

## 开始分享

[选源后失败](#选源后无法开始分享) · [H264 失败](#windows-上-h264-分享失败)

分享失败时，点击电视下方的错误图标，查看原因、当前阶段的检查和 **复制失败信息**；按提示检查后再重试。

![分享失败提示：示例采集错误、建议检查，以及复制失败信息按钮。](../assets/guide/share-failure.zh-CN.dark.png#gh-dark-mode-only)

*示例 App 采集错误。实际原因和检查项取决于失败阶段。*

### 没有屏幕选择弹窗

房主打开选源器，点击 **浏览器 → 选择画面**。出现系统提示时允许录屏，然后选择要分享的屏幕、窗口或标签页。

如果没有弹窗，请在电脑上通过完整的 HTTPS 邀请打开房间后重试。本机的 `localhost` 页面也可以使用浏览器录屏。若缺的是 App 来源，请看[找不到窗口或屏幕](#app-找不到窗口或屏幕)。

### App 找不到窗口或屏幕

在分享电脑上保持 App 运行，点击站点顶部的 **App**，在本机确认页核对站点并授权。
浏览器询问本地网络权限时允许访问，再刷新来源列表；之前拒绝过则先检查当前站点的权限。

选源器会区分以下情况：

| 提示 | 处理方法 |
| --- | --- |
| 未能连接 Piik App | 确认 App 正在运行，且当前站点已获得授权。关闭其他正在使用 App 的闲置 Piik 标签页后刷新列表；最多两个页面可以同时使用 App 的原生采集或收看功能。 |
| Piik App 与当前页面不兼容 | 更新 Piik App 并刷新页面。 |
| Piik App 采集功能当前不可用 | 查看 App 诊断信息中的采集和编码能力，检查编码设置，或使用浏览器采集。 |
| 未能读取 App 的窗口和屏幕列表 | 刷新重试；若持续失败，请导出同一次尝试的 App 和网页诊断报告。 |
| 暂无可用来源 | 已成功读取列表，但当前分类没有可选来源，可以查看其他分类。 |

本地网络权限用于让网页连接 App。连接后媒体仍失败时，检查[WebRTC 设置](./network.zh-CN.md#浏览器限制了-webrtc)。

### 选源后无法开始分享

1. 点击电视下方的错误图标，复制失败信息。若提示 App 断开或超时，确认 App 能响应，点击站点顶部的 **App** 重新连接，并允许浏览器访问本地网络。
2. 如果选中的来源启动失败，先试普通窗口，再试 **浏览器** 选源。浏览器无法读取时，保持来源打开并允许系统录屏。摄像头被其他程序独占时，先关闭占用它的程序。
3. 如果只有 Windows App 采集失败，试「自动」或 VP8，并按[显卡排查](#windows-上-h264-分享失败)检查。媒体连接报错时，检查[WebRTC 设置](./network.zh-CN.md#浏览器限制了-webrtc)和本地网络权限。若提示 [HTTP 403](#创建房间返回-403)，检查站点配置。

仍失败时，[收集同一次尝试的网页与 App 报告](#反馈问题)，附上来源类型和复制的失败信息。

### Windows 上 H264 分享失败

1. **用同一来源对比编码。** 在 **分享设置 → 画面 → 画面细调** 中，将视频编码从 **H264** 改为 **自动** 或
   **VP8**，重新开始分享。如果 VP8 正常，可以先用它，再排查 H264 路径。

<details>
<summary>需要使用 H264 时，检查驱动和 Chrome 设置</summary>

1. **更新后重启。** 更新 Piik App 和 Chrome，并从电脑或显卡厂商的官方网站安装适合本机的
   显卡驱动。双显卡笔记本应检查两块显卡的驱动，安装后重启电脑。
2. **Chrome 检查图形加速和首选显卡。** 在 Chrome **设置 → 系统** 中检查「使用图形加速
   （如果可用）」，此前关闭的话可开启并重启 Chrome（[Google 设置说明](https://support.google.com/meet/answer/10058482?hl=zh-Hans)）。
   Windows 多显卡电脑还可以进入 **设置 → 系统 → 屏幕 → 显示卡（图形）**，
   选择或添加 Chrome（`chrome.exe`），在 **选项** 中选择 **高性能** 并保存。
   完全退出 Chrome 后重新打开再试；没有改善就恢复 **让 Windows 决定**
   （[微软显卡设置说明](https://support.microsoft.com/en-us/windows/hardware/display-graphics/optimizations-for-windowed-games-in-windows-11)，英文）。

Chrome 的首选显卡设置用于浏览器采集，Piik App 会单独选择原生编码器。
仍然失败时，[收集报告](#反馈问题)并保留编码对照结果；两种编码都失败时，也检查 [WebRTC 限制](./network.zh-CN.md#浏览器限制了-webrtc)。

</details>

<span id="room-no-picture"></span>

### 画面连接不上

房间能打开，但观众收不到画面？请房主看看预览，按你们看到的情况选择办法。[没有可用的媒体线路](./no-media-route.zh-CN.md)

<span id="playback-stalls"></span>

### 画面模糊、卡顿或中断

1. 卡顿时请房主同时看预览。预览也卡住时，检查来源是否仍在更新、游戏是否占满 CPU 或 GPU，再到 **分享设置 → 画面** 单独调低分辨率或帧率对照。
2. 预览流畅时，问另一位观众是否也卡。如果只有你遇到周期性停顿，可试 **增加播放缓冲**。观察同一段运动画面；若卡顿持续或操作延迟过高，恢复原设置，再换浏览器或热点对照。
3. 如果所有观众都卡，让房主改分享一个普通窗口。如果这个窗口流畅，再打开下面的 Windows 编码检查。

<details>
<summary>Windows 房主 · 查看实际使用的视频编码</summary>

所有人都卡时，请房主在 **连接详情 → 视频编码** 查看实际编码。Windows 上 H264 不可用、检测未完成或达不到所选帧率时，「自动」可能选用 VP8。软件编码会占用游戏所需的 CPU。浏览器采集可按[显卡排查](#windows-上-h264-分享失败)检查，或改用 App 窗口／屏幕采集对照。H264 检测未通过时继续使用「自动」或 VP8。

</details>

若分享已经结束，查看电视下方的原因。[刷新前导出卡顿时段的报告](#反馈问题)，包括房主、受影响观众以及负责采集的 App。

### 游戏黑屏或进入游戏后停止分享

房主先看自己的预览。如果预览也是黑的，确认选中的是游戏窗口或显示游戏的屏幕。把游戏切到无边框窗口模式，再看预览。

游戏仍黑屏时，改分享普通窗口。如果普通窗口能显示，再换用 App 或 **浏览器** 的另一种选源方式分享游戏。受保护的内容可能无法采集。

如果进入游戏后 Piik 退回未分享状态，查看电视下方的失败原因，按[分享启动排查](#选源后无法开始分享)操作。
[反馈报告](#反馈问题)中请附上游戏名称和窗口模式。

### HDR 画面过亮或颜色发白

如果观众看到的亮部发白，而房主屏幕的颜色正常，请房主在 Windows App 里改选 **程序 / 窗口** 或 **屏幕** 后重新分享。App 会将 HDR 画面转为适合观看的 SDR。

继续用 **浏览器** 分享时，可在 Windows 显示设置里暂时关闭 HDR，再重新选源。已经过曝的亮部需要重新采集，调整码率或分辨率无法补回细节。

仍然异常时，请附上 HDR 设置、显卡／显示器型号及源画面与观众画面的对照。
技术背景见 [HDR 采集说明（英文）](../research/media-fidelity.md#hdr-to-sdr)。

### Windows 分享时出现黄框

Windows 用黄色边框标出正在采集的窗口或屏幕。App 检测到采集能力支持时，
选源器会提供 **显示采集边框** 开关，默认关闭；系统权限或其他正在进行的采集
仍可能要求显示边框。Windows 10 的采集接口没有这个开关。

#### Windows 11 关闭开关后仍有黄框

1. 从 Piik 的 **程序 / 窗口** 或 **屏幕** 列表选源，保持 **显示采集边框** 关闭。
   通过浏览器选源时，采集标识由浏览器管理。
2. 停止其他软件或标签页对同一窗口、屏幕的采集，再重新开始分享。
3. 如果之前拒绝了无边框采集权限，在 Windows 隐私设置中检查 **屏幕截图边框**。
   支持该设置页的系统也可以按 **Win+R**，输入 `ms-settings:privacy-graphicscapturewithoutborder` 打开。

Windows 需要用户授权；其他采集要求显示边框时，边框仍会保留
（[微软接口说明](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturesession.isborderrequired)，英文）。
仍未解决时，请附上 Windows 版本和 [App 报告](#反馈问题)。

<details>
<summary>进阶：Windows 10 可选处理方法</summary>

#### Windows 10 可选处理方法

[DWM Custom Projection Border](https://windhawk.net/mods/dwm-custom-projection-border)
是适用于 x64（64 位）Windows 的 Windhawk 第三方模组，可以在保持原有采集方式的情况下隐藏黄框。
它会修改 Windows 桌面合成器的行为，也会影响其他软件的采集提示。
使用前请核对模组要求的 Windows 版本。

1. 从[官方网站](https://windhawk.net/)安装 Windhawk。
2. 打开 Windhawk 全局的 **设置 → 高级设置 → 更多高级设置**，
   在 **包含的进程列表（Process inclusion list）** 中追加一行 `dwm.exe` 并保存，保留已有条目。
3. 搜索并安装 **DWM Custom Projection Border**，在模组设置中开启
   **Disable border（关闭边框）** 并保存。
4. 在 Piik 中停止后重新开始分享，检查黄框是否消失。

恢复原状时，禁用该模组并重新开始分享。如果 `dwm.exe` 这一项是专门为该模组添加的，
也可以移除。若桌面出现异常，或 Windows 更新后不再兼容，先禁用模组。

最新操作说明见[模组作者说明](https://github.com/ramensoftware/windhawk-mods/blob/main/mods/dwm-custom-projection-border.wh.cpp)
和 [Windhawk 进程设置文档](https://github.com/ramensoftware/windhawk/wiki/Injection-targets-and-critical-system-processes)（英文）。

</details>

<span id="mobile-stop"></span>

### 全屏或休眠后播放异常

手机房主想结束分享时，返回分享页并点击 **停止分享**。如果正在远控桌面，从画面底边打开抽屉即可操作。见[远程控制](./remote-control.zh-CN.md)。

- **播控按钮隐藏了：** 轻点画面即可重新呼出；正在远控时，使用电视底边的抽屉拉手。
- **没有全屏按钮或点击失败：** 将邀请链接复制到独立浏览器打开，例如安卓 Chrome 或
  iPhone Safari，避免使用聊天软件的内置浏览器。不支持系统全屏时，可用 **剧场模式** 放大网页内的画面。
- **全屏后 Piik 播控不见了：** 浏览器进入了自带的视频播放器。退出全屏、改用 **剧场模式**，
  即可保留 Piik 播控、弹幕和远控操作。
- **手机全屏仍有黑边：** 画面默认保持原始比例，可尝试横屏，或用播控上的 **切换画面适配**
  切换 **等比铺满** 或 **拉伸铺满**。如果已进入浏览器自带的视频播放器，先退出全屏再使用
  Piik 的画面适配。见[观看操作](./getting-started.zh-CN.md#加入朋友的房间)。
- **休眠或挂起后分享中断：** 唤醒设备，回到分享标签页，必要时重新开始分享。
  浏览器或系统挂起可能中断采集和播放。

**安卓切换应用后分享停了。** 回到 Piik 分享页，点击 **开始分享**，重新选择画面并确认系统的屏幕分享提示。如果 Piik App 已退出，先重新打开它。

如果反复出现，下一次开始分享前先选 **帮助 → 诊断**，确认重新加载网页。开始分享后切换应用，等问题再次出现。回到同一个分享页，点 **帮助 → 网页报告**。提供这次尝试的报告，并附上 Piik 版本、手机型号、安卓版本和切换到的应用名称。

## 手柄

### 手柄没有响应

1. 房主通过 App 分享窗口或屏幕，并开启 **远程控制**。
2. 按[支持的平台与手柄设置](./remote-control.zh-CN.md#手柄)检查房主端。
   外部驱动由房主从官方渠道安装，Piik 不附带 SDK 或驱动；安装后重新开启远程控制。
3. 观众连接标准布局手柄并按一下按钮，让浏览器识别；取得远程控制权后，Piik 自动使用
   浏览器标准映射下的第一个已连接手柄。保持观看页面在前台，在游戏中加入对应玩家；
   手柄位已满时，断开不使用的手柄或结束该观众的远程控制。

观众只需使用浏览器，驱动检查与安装在房主电脑完成。

## 反馈问题

在 GitHub [反馈问题](https://github.com/TNTcraftHIM/Piik/issues)时，写明设备、点了什么、看到了什么即可，无需日志。分享失败时，房主可点击电视下方的错误图标，复制提示文字。

<details>
<summary>需要报告时 · 收集诊断信息</summary>

请附上 Piik 版本、系统与浏览器、发生时间、预期结果和复现步骤。
采集问题还需说明来源类型、编码、显卡／驱动，以及其他来源或 VP8 是否正常；网络问题说明所用网络类型。

先开启诊断，重现一次，再在刷新前导出：

- **网页：** 打开 **帮助 → 诊断**，确认刷新后重现问题，再用 **帮助 → 网页报告** 下载。分享失败时，电视下方的错误图标还可复制失败信息，
  包含网页版本、提示和错误编号，不包含邀请链接或来源名称。
- **桌面 App 采集或远控：** 还需在房主 App 模式选择页开启 **诊断启动**，随后在终端按 `D` 导出 App 报告。
- **连接失败：** 收集受影响观众和房主同一次尝试的报告；自部署 SFU 还需服务端报告。

报告保存在本机，分享前请检查私人信息；[诊断与导出](../../cmd/piik-app/README.zh-CN.md#诊断)说明报告内容。
无法收集日志时，请提供完整错误文字与复现步骤。

其他指南可在[文档中心](./README.zh-CN.md)找到。

</details>
