# 问题排查

[English](./troubleshooting.md) · 简体中文 · [文档中心](./README.zh-CN.md)

按症状查找下方说明，依次尝试，恢复正常后就不必继续。
仍有问题时，请在刷新前[收集诊断报告](#反馈问题)。

## 常见问题

- [打开 App 与加入房间](#打开-app-与加入房间)：启动、邀请链接、证书与房间准入。
- [开始分享](#开始分享)：来源列表、采集权限与编码器。
- [画面与播放](#画面与播放)：连接、画质、游戏采集与全屏。
- [声音与浏览器权限](#声音与浏览器权限)：来源声音、语音、回声与远程控制。
- [手柄](#手柄)：手柄入口、房主驱动与游戏识别。
- [进阶网络排查](#进阶网络排查)：WebRTC、STUN、校园网与虚拟局域网。

## 打开 App 与加入房间

### App 启动失败或没有打开网页

1. 查看启动页面和终端中的原因。App 仍在运行时，可复制显示的地址，在浏览器中打开。
2. 本地模式列出多个地址时，选择朋友能访问的网卡和 IP，见[本地邀请排查](#本地邀请打不开)。
3. 仍然失败时，开启 **诊断启动** 后重试，保留完整错误和 [App 报告](#反馈问题)。

### macOS 提示已损坏或无法验证开发者

当前 Mac 版本尚未进行 Developer ID 签名和 Apple 公证，首次打开可能被系统拦截；
仅凭弹窗措辞，不能断定下载文件真的损坏。

1. 从项目 Releases 下载对应的 Mac ZIP，核对同一版本公布的 SHA-256。
   在终端运行 `shasum -a256 ~/Downloads/piik-app-darwin-arm64.zip`；
   Intel Mac 将文件名中的 `arm64` 换为 `amd64`。校验不一致时应重新下载，不要绕过警告。
2. 把完整的 `Piik App.app` 移到「应用程序」，尝试打开后，在
   **系统设置 → 隐私与安全性 → 仍要打开** 中确认。
   具体步骤见 [Apple 首次打开说明](https://support.apple.com/zh-cn/102445)。
3. 如果没有「仍要打开」，且已确认官方 ZIP 的校验值一致，可在终端仅移除这个 App
   的下载隔离标记，再重新打开：

   ```sh
   xattr -dr com.apple.quarantine "/Applications/Piik App.app"
   ```

保留在其他位置时，换成 App 的实际路径。保持系统整体安全检查开启。

### 公网邀请创建失败或出现 1033

App 的 **公网邀请** 通过 Cloudflare Tunnel 提供临时网页地址。
该服务的可达性会随网络而变化，[Quick Tunnels 不保证持续可用](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/#limitations)。
`public invitation service exited before connecting` 表示辅助程序在连接完成前退出；
`exit status 1` 本身不能说明具体原因。
[Cloudflare 的 1033 说明](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1033/)（英文）
表示该地址当前没有可用的隧道连接。这与网页能打开、但显示「没有可用的媒体线路」是不同的问题。

1. **观众先确认链接。** 请房主确认 App 仍在运行、电脑未休眠，并发送当前邀请。
   App 重新启动后应使用新链接，旧地址可能失效。
2. **房主查看错误详情。** 确认已完整解压 App 程序包；保留启动页面或终端的完整错误，
   包括退出码后的详细信息。开启 **诊断启动** 后再试。
3. **对照网络。** 可用手机热点重试，检查 DNS、代理或防火墙是否阻止 Cloudflare Tunnel。
   只调整相关规则；学校或公司的网络应联系管理员。

<details>
<summary>进阶：隧道错误、代理与 7844 端口</summary>

使用代理时，请确认它实际覆盖 `cloudflared` 进程。仅开启浏览器代理或设置
`HTTP_PROXY`／`HTTPS_PROXY`，不会让当前随包的隧道程序自动走代理。

错误详情可以帮助区分失败的环节：

| 错误中出现 | 检查什么 |
| --- | --- |
| `failed to request quick Tunnel`、`api.trycloudflare.com` | 临时地址申请失败。查看后面的具体原因：域名解析错误检查 DNS；连接超时检查 HTTPS 出站连接、代理或服务状态。 |
| QUIC 超时、`dial tcp ...:7844` 或 `TLS handshake with edge` | 到 Cloudflare 隧道节点的连接失败。检查 `cloudflared` 的出站规则，包括代理或游戏加速器是否影响该连接。 |

Piik 已启用 QUIC（UDP）失败后尝试 HTTP/2（TCP），两者都使用出站端口 `7844`。
如果两条线路都不可达，反复重试也无法解决；浏览器能访问普通网页不代表该端口可用。
具体要求见 [Cloudflare 连接排查](https://developers.cloudflare.com/tunnel/troubleshooting/)（英文），
无需在路由器上开放入站端口。

</details>

**暂时绕过公网邀请：** 保持 App 运行，打开[在线版](https://demo.piik.tv)或其他可访问站点，
[授权 App 采集](./getting-started.zh-CN.md#通过已有站点使用-app)，再发送新站点的房间邀请；原链接不会转到这个房间。
在线版无需站点口令，仍仅使用 P2P，不提供 SFU 兜底。
网页能打开但画面连不上时，转到[画面连接排查](#画面连接不上)。
如果打不开的是自建站点而非 App 的临时地址，请联系该站点管理员检查服务。

### 本地邀请打不开

浏览器提示连接超时、Piik 页面都打不开时，先检查网页访问；这时还没有进入 P2P 连接。

1. 保持房主 App 运行，在 **本地房间** 选择朋友能访问的网卡地址，发送完整邀请链接。
   两台设备需处于可互访的局域网或同一个虚拟局域网；访客 Wi-Fi 可能隔离设备。
2. Windows 房主打开 **Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙**，
   检查当前运行的 `piik-app.exe`，允许所用的网络类型。虚拟网卡可能被识别为 **公用网络**；
   需要更小范围时，可在高级规则中限定该虚拟网卡和网段。
3. 更新后换了解压目录，也要检查规则是否仍指向旧文件。系统未弹出询问不代表已经放行，
   可在上述页面手动添加当前 App。保持防火墙开启，只放行需要的应用。

App 提示 **本地端口不可用** 时，先关闭占用它的旧 Piik 实例。如果其他程序需要这个端口，
可用 `--port 9876` 启动 Piik，再发送新生成的邀请。网页和本地 STUN 端口都需要可用；
只修改链接里的端口不会改变服务的实际位置。

放行操作可能需要管理员权限，参阅 [Microsoft 说明](https://support.microsoft.com/zh-cn/windows/security/firewall/risks-of-allowing-apps-through-windows-firewall)。
网页能打开但画面连不上时，再按[画面连接排查](#画面连接不上)检查媒体线路。

### 本地 HTTPS 证书提示

Piik App 的 **本地房间**，以及启用 `TLS_SELF_SIGNED=true` 的服务端，会自行生成本地证书。
它没有经过公共证书机构签发，因此浏览器会先显示证书警告。

1. 确认网址与房主准备分享的地址一致。
2. 打开警告页的证书详情，将 **SHA-256 指纹** 与房主 App 终端中的 **本地证书 · SHA-256**，
   或服务端启动时的 **HTTPS certificate** 信息对照。异地使用时，可通过平时信任的聊天渠道向房主核对。
3. 指纹一致后，使用浏览器提供的 **高级 → 继续访问**；进入页面后，再正常允许麦克风或申请远控。

重启 App／服务端会更换临时证书，新指纹需要重新确认。App 不保存证书文件，也不安装系统受信任证书。
不要全局关闭浏览器的安全检查。如果浏览器不允许接受例外，请改用该设备已信任证书的 HTTPS 站点；
管理员可参阅 [HTTPS 部署说明](../operations/self-hosting.zh-CN.md#2-配置-https)。

以上只适用于预期中的本地自签名证书；普通公网 HTTPS 站点突然出现证书警告时，应让管理员排查原因。

### 房间号无法使用

先打开房主最新的完整邀请链接。房间号只在原 Piik 站点有效；站点开启空房间回收时，
旧房间也可能已被回收，由房主重新创建即可。参阅[加入房间](./getting-started.zh-CN.md#加入朋友的房间)。

站点房间号已用满时，稍后重试或使用其他 Piik 站点。管理员可配置
[空房间回收](../operations/self-hosting.zh-CN.md#1-配置并启动-piik)以收回闲置号码。
这与单个房间的观众人数上限不同。

### 创建房间返回 403

浏览器访问的网址不在服务端允许的范围内时，页面可能正常打开，但创建房间会被拒绝。
站点管理员可以按以下步骤检查：

1. 将 `PUBLIC_BASE_URL` 设为浏览器访问的站点地址，包含协议和非默认端口，不带路径。
2. `ALLOWED_ORIGINS` 不设置或留空时使用上述地址；需要多个地址时，用英文逗号列出全部
   可信地址。复制过配置示例的话，检查这里是否仍残留 `http://localhost:8787`。
3. 重启 Piik；使用 Compose 时运行 `docker compose up -d` 重建容器。刷新网页后重试。

配置正确但响应仍是 `Origin not allowed` 时，检查反向代理是否保留浏览器的 `Origin`
请求头。如果 403 来自代理或 WAF 本身，则应查看对应日志，不要通过关闭来源校验来绕过。
配置方法见 [Server 部署指南](../operations/self-hosting.zh-CN.md)。

## 开始分享

### 没有屏幕选择弹窗

按系统提示允许录制屏幕。浏览器屏幕采集需要 HTTPS 或 `localhost`，请在电脑上尝试分享。
在选源器中选择 **浏览器 → 选择画面**，打开浏览器的屏幕、窗口或标签页选择弹窗。
App 来源缺失则按下节操作。

### App 找不到窗口或屏幕

在分享电脑上保持 App 运行，点击站点顶部的 **App**，在本机确认页核对站点并授权。
浏览器询问本地网络权限时允许访问，再刷新来源列表；之前拒绝过则先检查当前站点的权限。

选源器会区分以下情况：

| 提示 | 处理方法 |
| --- | --- |
| 未能连接 Piik App | 确认 App 正在运行，且当前站点已获得授权。关闭其他正在使用 App 的闲置 Piik 标签页后刷新列表；最多两个页面可以同时使用 App 的原生采集或收看功能。 |
| Piik App 与当前页面不兼容 | 更新 Piik App 并刷新页面。 |
| Piik App 采集功能当前不可用 | 查看 App 诊断信息中的采集和编码能力，检查编码设置，或使用浏览器采集。 |
| 未能读取 App 的窗口和屏幕列表 | 刷新重试；若持续失败，请导出同一次尝试的 App 和网页诊断报告。 |
| 暂无可用来源 | 已成功读取列表，但当前分类没有可选来源，可以查看其他分类。 |

本地网络权限用于让网页连接 App，与下文的 WebRTC 媒体设置不同。
仅凭 App 未连接，不能确定是权限被拒绝。

### 选源后无法开始分享

点击电视下方的错误图标，可查看排查建议、复制失败信息，或开启网页诊断。

- **App 连接断开或请求超时**：确认 App 仍在运行且可以响应，点击站点顶部的 **App** 完成连接。
  浏览器询问本地网络权限时允许访问。超时只说明请求未及时完成，不能据此认定显卡故障。
- **App 未能启动所选来源**：先换一个普通窗口或屏幕；再对照「浏览器」选源。
  Windows 上可试「自动」或 VP8，后续按[显卡排查](#windows-上-h264-分享失败)操作。
- **浏览器无法读取来源或缺少权限**：保持来源打开，允许系统录屏权限，回到分享页重新选源。
  摄像头还需检查设备是否正被其他程序独占。
- **媒体连接失败**：检查[浏览器 WebRTC 设置](#浏览器限制了-webrtc)和本地网络权限。
  **创建房间返回 403** 则检查[站点配置](#创建房间返回-403)。


仍然失败时，[收集同一次尝试的网页与 App 报告](#反馈问题)，附上复制的失败信息和所选来源类型。

### Windows 上 H264 分享失败

1. **用同一来源对比编码。** 在 **分享设置 → 画面 → 画面细调** 中，将视频编码从 **H264** 改为 **自动** 或
   **VP8**，重新开始分享。如果 VP8 正常，可以先用它，再排查 H264 路径。
2. **更新后重启。** 更新 Piik App 和 Chrome，并从电脑或显卡厂商的官方网站安装适合本机的
   显卡驱动。双显卡笔记本应检查两块显卡的驱动，安装后重启电脑。
3. **Chrome 检查图形加速和首选显卡。** 在 Chrome **设置 → 系统** 中检查「使用图形加速
   （如果可用）」，此前关闭的话可开启并重启 Chrome（[Google 设置说明](https://support.google.com/meet/answer/10058482?hl=zh-Hans)）。
   Windows 多显卡电脑还可以进入 **设置 → 系统 → 屏幕 → 显示卡（图形）**，
   选择或添加 Chrome（`chrome.exe`），在 **选项** 中选择 **高性能** 并保存。
   完全退出 Chrome 后重新打开再试；没有改善就恢复 **让 Windows 决定**
   （[微软显卡设置说明](https://support.microsoft.com/en-us/windows/hardware/display-graphics/optimizations-for-windowed-games-in-windows-11)，英文）。

首选显卡是浏览器侧的排查项，不保证 H264 可用。Piik App 单独选择原生编码器；Chrome 的首选显卡不会指定 App 的采集显卡。
仍然失败时，[收集报告](#反馈问题)并保留编码对照结果；两种编码都失败时，也检查 [WebRTC 限制](#浏览器限制了-webrtc)。

## 画面与播放

### 画面连接不上

**没有可用的媒体线路** 表示 Piik 还没有找到能把画面送到你设备上的连接。
网页和媒体使用不同的连接；仅凭这条提示还不能确定具体原因。

1. **重新尝试观看连接。** **重新连接** 可用时先点击，否则刷新观看页或重新打开邀请。
   每次等连接尝试结束，重试一两次即可；反复刷新无法解除网络限制。
2. **检查浏览器 WebRTC 设置。** 浏览器设置、VPN 或隐私扩展可能阻止房主或观众的媒体连接，
   具体操作见 [WebRTC 排查](#浏览器限制了-webrtc)。
3. **换个网络测试。** 例如试用手机热点。使用 VPN 或代理时，检查其 UDP 策略；受管理的网络请联系管理员。
4. **请另一网络的朋友加入。** 对方能正常看画面且有余力转发时，Piik 可能经由这位观众送到你这里。
   线路由 Piik 自动选择，能否帮上忙取决于这些连接是否可用。

仍然失败时，继续[进阶网络排查](#进阶网络排查)，并收集房主与受影响观众同一次尝试的报告。

### 画面模糊、卡顿或中断

短时变糊可能来自网络或编码负载的自动调整；反复出现或长期不恢复时，按下面的步骤对照：

1. **确认影响范围。** 是房主预览、所有观众，还是只有某位观众？记录大致时间，
   以及能否自行恢复。房主预览清楚并不保证观众的连接也正常。
2. **一次调整一项。** 房主可在 **分享设置 → 画面** 中先试较低的分辨率或帧率，
   检查游戏运行时 CPU／GPU 是否接近满载；受影响的观众可用另一浏览器或手机热点对照。
   将码率调高不一定有帮助。
3. **查看实际编码。** 展开房主的 **连接详情**，查看 **视频编码**。Windows 上，
   「自动」选择 VP8 可能是 H264 不可用、未能完成检测，或检测未达到所选帧率；
   软件编码会与游戏争用 CPU。使用「浏览器」选源时，可按[显卡排查](#windows-上-h264-分享失败)
   检查图形设置，或对照 App 的窗口／屏幕采集。App 会独立尝试可用的硬件编码器。
   不要仅凭 VP8 判断显卡故障，也不必强制使用检测未通过的 H264。
4. **保留问题发生时的报告。** 按[反馈说明](#反馈问题)收集房主和受影响观众的报告，
   App 采集还需 App 报告。画面持续不恢复时可尝试 **重新连接**；请先导出报告再刷新页面。

如果分享已自动停止，查看电视下方的具体原因，并按[分享启动排查](#选源后无法开始分享)操作；
如果仍在分享但观众看不到画面，按[连接排查](#画面连接不上)操作。

### 游戏黑屏或进入游戏后停止分享

先确认当前分享的是游戏窗口或游戏所在的屏幕，再尝试游戏的无边框窗口模式。
对照分享一个普通窗口，并在 App 选源与 **浏览器** 选源之间比较。
受保护的内容可能无法采集；某个游戏失败不代表所有来源都不可用。

如果进入游戏后 Piik 退回未分享状态，查看电视下方的失败原因，按[分享启动排查](#选源后无法开始分享)操作。
[反馈报告](#反馈问题)中请附上游戏名称和窗口模式。

### HDR 画面过亮或颜色发白

Windows App 的 **程序 / 窗口** 和 **屏幕** 采集会将 HDR 转成 SDR，再分享给观众。
**浏览器** 选源由浏览器负责采集，部分 HDR 来源可能过曝；这是当前的已知限制。
可改用 App 的上述分类，或在 Windows 显示设置中暂时关闭 HDR 后重新选源。
提高分辨率或码率无法恢复已经丢失的亮部细节。

仍然异常时，请附上 HDR 设置、显卡／显示器型号及源画面与观众画面的对照。
技术背景见 [HDR 采集说明（英文）](../research/media-fidelity.md#hdr-to-sdr)。

### Windows 分享时出现黄框

Windows 用黄色边框标出正在采集的窗口或屏幕。App 检测到采集能力支持时，
选源器会提供 **显示采集边框** 开关，默认关闭；系统权限或其他正在进行的采集
仍可能要求显示边框。Windows 10 的采集接口没有这个开关。

#### Windows 11 关闭开关后仍有黄框

1. 从 Piik 的 **程序 / 窗口** 或 **屏幕** 列表选源，保持 **显示采集边框** 关闭。
   通过浏览器选源时，采集标识由浏览器管理。
2. 停止其他软件或标签页对同一窗口、屏幕的采集，再重新开始分享。
3. 如果之前拒绝了无边框采集权限，在 Windows 隐私设置中检查 **屏幕截图边框**。
   支持该设置页的系统也可以按 **Win+R**，输入 `ms-settings:privacy-graphicscapturewithoutborder` 打开。

Windows 需要用户授权；其他采集要求显示边框时，边框仍会保留
（[微软接口说明](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturesession.isborderrequired)，英文）。
仍未解决时，请附上 Windows 版本和 [App 报告](#反馈问题)。

#### Windows 10 可选处理方法

### 全屏或休眠后播放异常

- **手机全屏仍有黑边：** 画面默认保持原始比例，可尝试横屏，或在 **播放设置** 中选择
  **等比铺满** 或 **拉伸铺满**。
- **全屏按钮无效：** 使用播放栏的 **全屏观看** 按钮。系统视频全屏由浏览器提供，
  见[观看操作](./getting-started.zh-CN.md#加入朋友的房间)。
- **休眠或挂起后分享中断：** 唤醒设备，回到分享标签页，必要时重新开始分享。
  浏览器或系统挂起可能中断采集和播放。

## 声音与浏览器权限

### 有画面但没有来源声音

1. 取消视频静音，并检查播放音量。
2. 房主应选择支持分享声音的来源，并在选源器中打开声音；可用声音取决于来源和平台。
3. 摄像头画面与麦克风输入分别选择。内置麦克风或 OBS 音频的用法，见[摄像头与音频输入](./sharing.zh-CN.md#摄像头与虚拟音频输入)。

### 听不到说话声

支持房间语音的版本中：

1. 双方都加入 **互动 → 语音**，由房主先选择 **开启房间语音**。
   加入只开始收听，每位发言者还需主动打开自己的麦克风。
2. 发言者检查浏览器的麦克风权限，以及 **麦克风设置** 中的输入设备和音量。
   使用麦克风需要 HTTPS 或 `localhost`。
3. 检查自己是否暂停收听或将对方本地静音。这些控制与视频静音分开；**暂停收听** 不会关闭自己的麦克风。

语音提示连接失败时，对照 [WebRTC 设置](#浏览器限制了-webrtc)及另一网络。
能看画面不代表语音连接正常。功能可用范围见[房间语音](./room-tools.zh-CN.md#房间语音)。

### 回声或传出了多余的应用声音

扬声器被麦克风再次收音时，可使用耳机。Windows App 屏幕采集支持
[排除语音软件的来源音频](./sharing.zh-CN.md#分享屏幕时排除语音软件的声音)，但不会消除声学回声。

虚拟麦克风在 Piik 闭麦后仍可听见时，暂时关闭 **系统声音** 对照。如果声音消失，
说明混音软件的播放输出也进入了来源音频。检查其播放／监听路由，或只分享需要的应用窗口音频。
Piik 的麦克风静音不会关闭这条独立来源。

### 无法使用麦克风或远程控制

1. 打开当前 App 生成的完整 HTTPS 邀请。本地邀请应先[确认证书](#本地-https-证书提示)。
   普通 HTTP 内网页面可以观看、聊天和加入语音收听，但不能使用需要安全上下文的麦克风、摄像头采集和远控接口。
   仅修改链接里的协议名不会开启 HTTPS；`localhost` 只代表当前设备。
2. 麦克风不可用时，检查当前站点的浏览器权限和所选输入设备。
3. 远控需更新房主 App 和站点，再刷新观众页面。房主必须使用 App 窗口／屏幕采集并开启远控；
   浏览器与摄像头采集不能接收远程输入。随后按[授权步骤](./room-tools.zh-CN.md#让朋友操作共享的电脑)操作。

浏览器不接受本地证书例外时，改用可访问的 **公网邀请** 或具有可信证书的 HTTPS 站点。

## 手柄

### 看不到「使用手柄」，或游戏不响应

1. 房主通过 App 分享窗口或屏幕，并开启 **远程控制**。
2. 按[支持的平台与手柄设置](./remote-control.zh-CN.md#手柄)检查房主端。
   外部驱动由房主从官方渠道安装，Piik 不附带 SDK 或驱动；安装后重新开启远程控制。
3. 观众连接手柄并按任意按钮，让浏览器识别，再选择 **使用手柄** 并取得控制权。
   在游戏中加入对应玩家；手柄位已满时先退出一个玩家。

观众只需使用浏览器，驱动检查与安装在房主电脑完成。

## 进阶网络排查

### 浏览器限制了 WebRTC

Piik 通过 WebRTC 传输画面和声音。禁用 WebRTC 或禁止未经代理的 UDP，可能使观众收不到画面，
甚至阻断本机网页与 App 之间的媒体连接；能选到来源并不代表这条连接可用。
仅隐藏本机 IP 地址不一定会阻止 WebRTC。

1. 使用默认设置、未安装 VPN 或隐私扩展的浏览器配置打开同一邀请进行对照。
   如果可以连接，再检查原配置中的 WebRTC 或 IP 泄露保护选项。
2. 恢复允许 WebRTC UDP 的策略。`disable_non_proxied_udp` 表示限制未经代理的 UDP，
   可以先与浏览器默认策略对比。Vivaldi 的选项位于 **设置 → 隐私和安全 → WebRTC IP 处理**，
   开启 **广播 IP 以获得最佳 WebRTC 性能**。Chrome 中的扩展也可能控制该策略，即使浏览器没有显式开关。
3. 修改后刷新受影响的 Piik 页面，重新尝试分享或观看。由学校或公司统一管理的设置，请联系管理员检查。

允许这些连接可能向 WebRTC 对端暴露网络地址，只调整相关选项即可。
参考 [Chrome 策略说明](https://developer.chrome.com/docs/extensions/reference/api/privacy#property-network)
和 [Vivaldi 隐私设置](https://help.vivaldi.com/desktop/privacy/privacy-settings/)（英文）。

### STUN、IPv6 与路由器检查

NAT 让多台设备共用一个上网地址。有些路由器或运营商网络会使直连更困难；
防火墙和浏览器策略也可能阻止媒体。检查自己能够管理的部分：

1. **STUN 地址发现：** STUN 帮助发现直连地址，不负责转发画面。服务不可达时，可能聊天正常而媒体连不上。
   App 公网邀请已使用多个发现服务，单个 STUN 报错不代表全部线路失败。
   自部署管理员应检查 `STUN_URLS` 是否指向可达的 UDP 服务；HTTP 反向代理不能转发 STUN。
   App 用户可在启动公网邀请前设置 [`PIIK_STUN_URLS`](../standards/configuration.md#piik-app-configuration)，
   替换所有内置发现地址。请选择信任的服务，因为它会接收到参与者的公网 IP。
2. **IPv6：** 宽带、路由器和双方设备都有可用 IPv6 时，Piik 可以在 IPv4 之外尝试这条直连路径。
   同时保留 IPv4；IPv6 仍受防火墙约束。
3. **家庭路由器：** 支持的 UPnP、PCP 或 NAT-PMP 可以让 App 原生媒体连接申请端口映射；
   纯浏览器采集不会申请。光猫和路由器都做 NAT 时，可按对应型号的桥接或 AP 模式说明减少一层，
   修改工作模式前先备份配置。运营商共享公网地址（CGNAT）位于上游，需向运营商咨询公网 IPv4 或 IPv6 服务。

路由器菜单随型号而异，可参考厂商的
[IPv6 条件](https://support.google.com/googlehome/answer/6361450?hl=zh-Hans)、
[UPnP 说明](https://support.google.com/googlehome/answer/6274337?hl=zh-Hans)、
[双重 NAT 示例](https://www.tp-link.com/us/support/faq/3113/)及
[WebRTC 连接说明](https://webrtc.org/getting-started/peer-connections)（后两篇为英文）。
结合双方报告判断原因。

### 校园网或严格 NAT

先用手机热点打开同一邀请对照。热点可用时，优先排查原网络的共享出口或防火墙限制。

经常使用时，管理员可在自建 Piik 站点[启用 SFU 媒体兜底](../operations/self-hosting.zh-CN.md#可选启用媒体兜底)。
页面提供 **隐私模式** 时，房主应在分享前关闭；配置为 **服务器转发** 的站点已经强制使用 SFU。
保持 App 运行，打开新站点，点击 **App** 完成本机授权，再发送该站点的邀请。

公开站点 `demo.piik.tv` 和 App 的 **公网邀请** 仅提供 P2P。目前 P2P 和 SFU 媒体均需要 UDP。
单独搭建服务器不能绕过完全禁止媒体 UDP 的网络；需换网络或由管理员放行。

### 可选：虚拟局域网

不便部署服务器时，也可以尝试第三方虚拟局域网，让朋友先加入同一虚拟网络。
例如 [UU 官方教程](https://uu.163.com/blog/lan-multiplayer-guide-net.html)提供了「局域网联机」和「通用联机」入口。
选择通用局域网组网功能，而不是仅限某个游戏的加速；工具需提供可互访的虚拟 IPv4 地址，
并同时支持 Piik 的网页访问和 WebRTC UDP。

1. 所有参与者先运行组网工具，加入同一个虚拟局域网。
2. 如果工具提供的虚拟网卡和 IP 出现在 Piik App 的 **本地房间** 地址列表中，
   房主选择该地址进入并开始分享。打不开网页时，先按[本地邀请排查](#本地邀请打不开)
   检查 Windows 防火墙是否允许 Piik 通过该虚拟网络。
3. 将该地址下的完整 Piik 邀请链接发给朋友，不要发送 `localhost` 地址或只发房间号。
   网页能打开后，还需确认画面和声音正常；网页连通不代表媒体 UDP 一定可用。
4. 所有设备保持组网工具运行。工具的虚拟 IP 变化后，在 App 中重新选择地址并发送新邀请。

**本地房间** 会为所选虚拟 IP 生成 HTTPS 邀请，首次访问应先[确认证书](#本地-https-证书提示)。
随后支持的浏览器即可开麦、使用摄像头或远控，无需公网隧道；普通局域网的用法相同。
不可用时，检查[浏览器权限](#无法使用麦克风或远程控制)。连接详情中可查看所选媒体地址。

请使用已更新的 App，以发现经过路由的虚拟局域网地址。本方法需要可用的虚拟地址和媒体 UDP，
不适用于仅转发游戏流量的工具。防火墙、浏览器地址发现和第三方服务仍会影响可用性；仅与信任的朋友组网。

[ZeroTier](https://docs.zerotier.com/start/) 和 [Tailscale](https://tailscale.com/docs/how-to/quickstart) 也提供私有组网能力。
使用前需确认设备支持和上述条件；这些替代工具尚未与 Piik 实测。

有公网服务器的管理员可按 [frp 教程](../operations/self-hosting.zh-CN.md#可选通过-frp-转发已有服务)，
通过 frps 转发已有站点的网页和 SFU 端点；只转发网页不能同时转发 WebRTC 媒体。

## 反馈问题

请附上 Piik 版本、系统与浏览器、发生时间、预期结果和复现步骤。
采集问题还需说明来源类型、编码、显卡／驱动，以及其他来源或 VP8 是否正常；网络问题说明所用网络类型。

先开启诊断，重现一次，再在刷新前导出：

- **网页：** 使用页面的诊断按钮。分享失败时，电视下方的错误图标还可复制失败信息，
  包含网页版本、提示和错误编号，不包含邀请链接或来源名称。
- **App 采集：** 还需在 App 模式选择页开启 **诊断启动**，随后在终端按 `D` 导出 App 报告。
- **连接失败：** 收集受影响观众和房主同一次尝试的报告；自部署 SFU 还需服务端报告。
  房主上传成功或订阅建立，并不代表观众已经收到画面。

报告保存在本机，分享前请检查私人信息；[诊断与导出](../../cmd/piik-app/README.zh-CN.md#诊断)说明报告内容。
没有日志也可以反馈，但一张通用失败截图可能无法确定具体环节。

其他指南可在[文档中心](./README.zh-CN.md)找到。
