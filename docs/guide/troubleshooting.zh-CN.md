本页适用于 3.0 内测版；正式 2.x 请看 [2.6.1 问题排查](https://github.com/TNTcraftHIM/Piik/blob/v2.6.1/docs/guide/troubleshooting.zh-CN.md)。

## 打开 App 与加入房间

[本地证书](#本地-https-证书提示) · [邀请与密码](#邀请或密码被拒绝) · [域连接](#网页能打开但域连接不上)

### App 启动失败或没有打开网页

1. 查看启动页面和终端中的原因。App 仍在运行时，可复制显示的地址，在浏览器中打开。
2. 本地模式列出多个地址时，选择朋友能访问的网卡和 IP，见[本地邀请排查](#本地邀请打不开)。
3. 仍然失败时，在 App 启动页打开 **帮助 → 诊断** 后重试，保留完整错误和 [App 报告](#反馈问题)。

### 安卓 APK 无法安装

使用本次提供的 3.0 测试 APK，安装步骤见 [App 使用指南](./getting-started.zh-CN.md#用-piik-app-分享)。
安卓提示时，允许本次使用的浏览器或文件管理器安装下载的 APK。

安卓提示签名或软件包冲突时，先核对 APK 是否与已安装 App 属于同一测试渠道。
不要为重试直接卸载或清除数据，这可能删除托管的房间和历史；切换渠道前先保留
[备份](../../prototype/channel-server/README.md#saved-data-and-files)。浏览器的身份和设置独立保存。

### macOS 提示已损坏或无法验证开发者

当前 Mac 版本未进行 Developer ID 签名和 Apple 公证。首次打开时，先校验下载文件，再为这个 App 放行：

若 macOS 提示恶意软件、「会损坏你的电脑」，或自动将 App 移到废纸篓，
请[保留完整提示和下载链接反馈](#反馈问题)，不要使用下方的隔离标记命令。

1. 使用该测试渠道提供的 Mac 构建，核对随包提供的 SHA-256。
   在终端运行 `shasum -a256 ~/Downloads/piik-app-darwin-arm64.zip`；
   Intel Mac 将文件名中的 `arm64` 换为 `amd64`。校验不一致时应重新下载，不要绕过警告。
2. 把完整的 `Piik App.app` 移到「应用程序」，尝试打开后，在
   **系统设置 → 隐私与安全性 → 仍要打开** 中确认。
   具体步骤见 [Apple 首次打开说明](https://support.apple.com/zh-cn/102445)。
3. 如果没有「仍要打开」，且已确认该 ZIP 的校验值一致，可在终端仅移除这个 App
   的下载隔离标记，再重新打开：

   ```sh
   xattr -dr com.apple.quarantine "/Applications/Piik App.app"
   ```

保留在其他位置时，换成 App 的实际路径。保持系统整体安全检查开启。

### 公网邀请创建失败或出现 1033

App 的 **公网邀请** 通过 Cloudflare Tunnel 提供临时网页地址。
[错误 1033](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1033/)（英文）
表示隧道已断开。出现 `public invitation service exited before connecting` 或 `exit status 1` 时，
查看后续的详细错误，按下方步骤排查。

1. **观众先确认链接。** 请房主确认 App 仍在运行、电脑未休眠，并发送当前邀请。
   App 重新启动后应使用新链接，旧地址可能失效。
2. **房主查看错误详情。** 确认已完整解压 App 程序包；保留启动页面或终端的完整错误，
   包括退出码后的详细信息。在启动页打开 **帮助 → 诊断** 后再试。
3. **对照网络。** 可用手机热点重试，检查 DNS、代理或防火墙是否阻止 Cloudflare Tunnel。
   只调整相关规则；学校或公司的网络应联系管理员。

<details>
<summary>进阶：隧道错误、代理与 7844 端口</summary>

使用代理时，请确认它实际覆盖 `cloudflared` 进程。仅开启浏览器代理或设置
`HTTP_PROXY`／`HTTPS_PROXY`，不会让当前随包的隧道程序自动走代理。

错误详情可以帮助区分失败的环节：

| 错误中出现 | 检查什么 |
| --- | --- |
| `failed to request quick Tunnel`、`api.trycloudflare.com` | 临时地址申请失败。查看后面的具体原因：域名解析错误检查 DNS；连接超时检查 HTTPS 出站连接、代理或服务状态。 |
| QUIC 超时、`dial tcp ...:7844` 或 `TLS handshake with edge` | 到 Cloudflare 隧道节点的连接失败。检查 `cloudflared` 的出站规则，包括代理或游戏加速器是否影响该连接。 |

Piik 在 QUIC（UDP）失败后会尝试 HTTP/2（TCP），请允许两者使用出站端口 `7844`。
具体要求见 [Cloudflare 连接排查](https://developers.cloudflare.com/tunnel/troubleshooting/)（英文），
无需在路由器上开放入站端口。

</details>

临时公网地址不可用时，也可以使用已有的 **3.0** 域。
需要改用[局域网使用](./network.zh-CN.md#可选虚拟局域网)时，先结束当前分享、正常退出并重新打开 App，再选择该模式。
公开 Demo 和已发布的 2.x 站点属于不同版本。长期域名打不开时，请该域的管理员检查服务。
网页恢复后，再分别检查[聊天与托管](#聊天或历史记录加载不出来)或[点对点连接](#画面连接不上)。

### 本地邀请打不开

浏览器连接超时、Piik 页面打不开时，先检查到房主 App 的访问：

1. 保持房主 App 运行，在 **局域网使用** 选择朋友能访问的网卡地址，发送完整邀请链接。
   两台设备需处于可互访的局域网或同一个虚拟局域网；访客 Wi-Fi 可能隔离设备。
2. Windows 房主打开 **Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙**，
   检查当前运行的 `piik-app.exe`，允许所用的网络类型。虚拟网卡可能被识别为 **公用网络**；
   需要更小范围时，可在高级规则中限定该虚拟网卡和网段。
3. 更新后换了解压目录，请更新仍指向旧文件的防火墙规则；需要时手动添加当前 App，保持防火墙开启。

App 提示本地端口不可用时，先关闭占用它的旧 App 实例。
需要指定端口时，按当前 [App 运行设置](../../prototype/channel-server/README.md#local-app-link)配置，
再发送新生成的邀请；只修改链接里的端口不会移动实际服务。

放行操作可能需要管理员权限，参阅 [Microsoft 说明](https://support.microsoft.com/zh-cn/windows/security/firewall/risks-of-allowing-apps-through-windows-firewall)。
网页能打开但画面连不上时，再按[画面连接排查](#画面连接不上)检查媒体线路。

### 本地 HTTPS 证书提示

Piik App 的本地网络邀请使用临时自签名 HTTPS 证书，浏览器可能先显示证书警告。

1. 确认网址与房主准备分享的地址一致。
2. 打开警告页的证书详情，将 **SHA-256 指纹** 与 App 终端中的 **Certificate SHA-256** 对照。异地使用时，可通过平时信任的聊天渠道向 App 使用者核对。
3. 指纹一致后，使用浏览器提供的 **高级 → 继续访问**；进入页面后，再正常允许麦克风或申请远控。

重启 App 会更换临时证书，新指纹需要重新确认。App 不保存证书文件，也不安装系统受信任证书。
不要全局关闭浏览器的安全检查。如果浏览器不允许接受例外，请改用该设备已信任证书的 HTTPS 站点；
管理员可参阅 [3.0 运行说明](../../prototype/channel-server/README.md#run)（英文）。

以上只适用于预期中的本地自签名证书；普通公网 HTTPS 站点突然出现证书警告时，应让管理员排查原因。

### 邀请或密码被拒绝

打开当前完整的 3.0 链接，包括其中的邀请部分。域邀请和房间邀请不同：
私密域可能要求域邀请或口令，私密房间可能另需房间邀请或密码。
邀请重置后，请向对应的域主或房主索取新链接。
使用原浏览器配置可保留已有身份；隐私模式或另一浏览器配置使用各自保存的凭据。

提示需要更新时，使用匹配的 3.0 App、网页和 Server，再刷新页面。
2.x App 或域不能替代当前测试端。

### 网页能打开但域连接不上

先看页面顶部的连接状态。持续断开时，用另一浏览器或网络打开同一链接，并保留完整错误。

#### 创建房间返回 403

访问域或创建房间时收到 HTTP 403，管理员需检查网页和 WebSocket 是否到达同一个域服务、浏览器实际访问的来源地址是否获准，
见 [运行配置](../../prototype/channel-server/README.md#run)（英文）。
代理或 WAF 返回的 HTTP 错误要查对应日志，不要关闭来源校验来绕过。

## 聊天与文件

### 聊天或历史记录加载不出来

1. 看页面顶部的域连接状态；断开时点击 **重新连接**。
2. 看房间提示。**房间暂不可用** 表示需要恢复托管：Browser 托管的房间要保持原网页打开，App 托管的房间要恢复对应 App。打开你自己的 App 不会接管别人的房间。
3. 房间在线但读取失败时，点击 **加载消息** 重试并保留错误。存储错误由房间托管端排查，也应收集它的报告。

聊天、历史、消息表情与附件描述通过域连接传输，不需要媒体 UDP。
聊天正常而画面、语音或文件不通时，再按对应活动排查。

### 附件打不开或下载不了

1. 保持发送页，或持有可读取副本的另一参与者在线。聊天中保留附件卡片，不代表文件内容始终可用。
2. 点击 **下载** 或 **查看图片**；传输等待时可点 **取消下载**，等来源或连接恢复后再试。
3. 消息能到、文件不能传时，查[点对点连接](./network.zh-CN.md)。附件描述通过聊天到达，文件内容仍走 P2P。
4. 浏览器提示保存失败时，查看下载列表、磁盘空间和目标目录权限，反馈时附上准确错误。

文件失败或取消不会结束房间聊天。不要为重试清除站点存储，这可能删除保留文件、身份或 Browser 托管的房间。

## 开始分享

[没有选源器](#没有屏幕选择弹窗) · [找不到窗口](#app-找不到窗口或屏幕) ·
[选源后失败](#选源后无法开始分享) · [H264 失败](#windows-上-h264-分享失败)

分享失败时，先读页面顶部的错误提示，保留提示原文与选源类型，再重试。
当前报告入口见[反馈问题](#反馈问题)。

### 没有屏幕选择弹窗

按系统提示允许录制屏幕。浏览器屏幕采集需要 HTTPS 或 `localhost`，请在电脑上尝试分享。
在选源器中选择 **浏览器 → 选择画面**，打开浏览器的屏幕、窗口或标签页选择弹窗。
App 来源缺失则按下节操作。

### App 找不到窗口或屏幕

在分享电脑上保持 App 运行，点击站点顶部的 **App**，在本机确认页核对站点并授权。
浏览器询问本地网络权限时允许访问，再刷新来源列表；之前拒绝过则先检查当前站点的权限。

选源器会区分以下情况：

| 提示 | 处理方法 |
| --- | --- |
| 未能连接 Piik App | 确认 App 正在运行，且当前站点已获得授权。若提示 App 忙碌，可关闭未使用的 Piik 页面后重试。 |
| Piik App 与当前页面不兼容 | 更新 Piik App 并刷新页面。 |
| Piik App 采集功能当前不可用 | 查看 App 诊断信息中的采集和编码能力，检查编码设置，或使用浏览器采集。 |
| 未能读取 App 的窗口和屏幕列表 | 刷新重试；若持续失败，请导出同一次尝试的 App 和网页诊断报告。 |
| 暂无可用来源 | 已成功读取列表，但当前分类没有可选来源，可以查看其他分类。 |

本地网络权限用于让网页连接 App。连接后媒体仍失败时，检查[WebRTC 设置](./network.zh-CN.md#浏览器限制了-webrtc)。

### 选源后无法开始分享

先读页面错误，再按选中的来源对照：

- **App 断开或请求超时：** 保持 App 运行，通过页面顶部的 **App** 完成连接；浏览器询问本地网络权限时允许访问。
- **App 未能启动来源：** 先换一个普通窗口或屏幕，再对照 **浏览器** 选源。H264 失败时，在分享前选择自动或 VP8。
- **设备权限未获允许：** 允许对应的系统／浏览器录屏或摄像头权限，保持来源打开，再次选源；检查摄像头是否被其他程序占用。
- **分享已开始，但观看者收不到：** 按[画面连接排查](#画面连接不上)操作。

仍失败时，收集[同一次尝试的报告](#反馈问题)。

### Windows 上 H264 分享失败

1. **用同一来源对比编码。** 在 **画质与声音 → 画面 → 画面细调** 中，将视频编码从 **H264** 改为 **自动** 或
   **VP8**，重新开始分享。如果 VP8 正常，可以先用它，再排查 H264 路径。
2. **更新后重启。** 更新 Piik App 和 Chrome，并从电脑或显卡厂商的官方网站安装适合本机的
   显卡驱动。双显卡笔记本应检查两块显卡的驱动，安装后重启电脑。
3. **Chrome 检查图形加速和首选显卡。** 在 Chrome **设置 → 系统** 中检查「使用图形加速
   （如果可用）」，此前关闭的话可开启并重启 Chrome（[Google 设置说明](https://support.google.com/meet/answer/10058482?hl=zh-Hans)）。
   Windows 多显卡电脑还可以进入 **设置 → 系统 → 屏幕 → 显示卡（图形）**，
   选择或添加 Chrome（`chrome.exe`），在 **选项** 中选择 **高性能** 并保存。
   完全退出 Chrome 后重新打开再试；没有改善就恢复 **让 Windows 决定**
   （[微软显卡设置说明](https://support.microsoft.com/en-us/windows/hardware/display-graphics/optimizations-for-windowed-games-in-windows-11)，英文）。

Chrome 的首选显卡设置用于浏览器采集，Piik App 会单独选择原生编码器。
仍然失败时，[收集报告](#反馈问题)并保留编码对照结果；两种编码都失败时，也检查 [WebRTC 限制](./network.zh-CN.md#浏览器限制了-webrtc)。

## 画面与播放

[画面连不上](#画面连接不上) · [模糊 / 卡顿](#画面模糊卡顿或中断) ·
[游戏黑屏](#游戏黑屏或进入游戏后停止分享) · [HDR 发白](#hdr-画面过亮或颜色发白) ·
[采集黄框](#windows-分享时出现黄框) · [全屏 / 休眠](#全屏或休眠后播放异常)

### 画面连接不上

先检查这一路分享，不要把所有房间活动当成同一条连接：

1. 确认分享者仍在分享且没有暂停，在该来源旁点击 **观看**；自动重试状态显示在对应画面卡片中。
2. 对照[浏览器 WebRTC 设置](./network.zh-CN.md#浏览器限制了-webrtc)，尤其是聊天正常、画面不通时。
3. 换用手机热点等其他网络，检查 VPN／代理的 UDP 策略；受管理的网络请联系管理员。

仍失败时继续[进阶网络排查](./network.zh-CN.md)，并记下同一房间的聊天和其他画面是否正常。

### 画面模糊、卡顿或中断

短时变糊可能来自网络或编码负载的自动调整；反复出现或长期不恢复时，按下面的步骤对照：

1. **确认影响范围。** 是分享者预览、所有观众，还是只有某位观众？记录大致时间，
   以及能否自行恢复。
2. **一次调整一项。** 分享者可在 **画质与声音 → 画面** 中先试较低的分辨率或帧率，
   检查游戏运行时 CPU／GPU 是否接近满载；受影响的观众可用另一浏览器或手机热点对照。
   将码率调高不一定有帮助。
3. **比较采集方式。** 停止这一路分享，在重新开始前选择自动或 VP8；用同一来源对照 App 窗口／屏幕采集与浏览器采集。软件编码可能与游戏争用 CPU；App 硬件编码与浏览器图形设置各自独立。
4. **保留发生时的证据。** 收集分享者与受影响观看者的[报告](#反馈问题)，App 采集还需 App 报告；重试前记下画面是否会自行恢复。

如果分享已自动停止，查看页面错误提示，并按[分享启动排查](#选源后无法开始分享)操作；
如果仍在分享但观众看不到画面，按[连接排查](#画面连接不上)操作。

### 游戏黑屏或进入游戏后停止分享

先确认当前分享的是游戏窗口或游戏所在的屏幕，再尝试游戏的无边框窗口模式。
对照分享一个普通窗口，并在 App 选源与 **浏览器** 选源之间比较。
受保护的内容可能无法采集。

如果进入游戏后 Piik 退回未分享状态，查看页面错误提示，按[分享启动排查](#选源后无法开始分享)操作。
[反馈报告](#反馈问题)中请附上游戏名称和窗口模式。

### HDR 画面过亮或颜色发白

Windows App 的 **程序 / 窗口** 和 **屏幕** 采集会将 HDR 转成 SDR，再分享给观众。
**浏览器** 选源由浏览器负责采集，部分 HDR 来源可能过曝。
可改用 App 的上述分类，或在 Windows 显示设置中暂时关闭 HDR 后重新选源。
提高分辨率或码率无法恢复已经丢失的亮部细节。

仍然异常时，请附上 HDR 设置、显卡／显示器型号及源画面与观众画面的对照。
技术背景见 [HDR 采集说明（英文）](../research/media-fidelity.md#hdr-to-sdr)。

### Windows 分享时出现黄框

Windows 用黄色边框标出正在采集的窗口或屏幕。App 检测到采集能力支持时，
选源器会提供 **显示采集边框** 开关，默认关闭；系统权限或其他正在进行的采集
仍可能要求显示边框。Windows 10 的采集接口没有这个开关。

#### Windows 11 关闭开关后仍有黄框

1. 从 Piik 的 **程序 / 窗口** 或 **屏幕** 列表选源，保持 **显示采集边框** 关闭。
   通过浏览器选源时，采集标识由浏览器管理。
2. 停止其他软件或标签页对同一窗口、屏幕的采集，再重新开始分享。
3. 如果之前拒绝了无边框采集权限，在 Windows 隐私设置中检查 **屏幕截图边框**。
   支持该设置页的系统也可以按 **Win+R**，输入 `ms-settings:privacy-graphicscapturewithoutborder` 打开。

Windows 需要用户授权；其他采集要求显示边框时，边框仍会保留
（[微软接口说明](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturesession.isborderrequired)，英文）。
仍未解决时，请附上 Windows 版本和 [App 报告](#反馈问题)。

#### Windows 10 可选处理方法

[DWM Custom Projection Border](https://windhawk.net/mods/dwm-custom-projection-border)
是适用于 x64（64 位）Windows 的 Windhawk 第三方模组，可以在保持原有采集方式的情况下隐藏黄框。
它会修改 Windows 桌面合成器的行为，也会影响其他软件的采集提示。
使用前请核对模组要求的 Windows 版本。

1. 从[官方网站](https://windhawk.net/)安装 Windhawk。
2. 打开 Windhawk 全局的 **设置 → 高级设置 → 更多高级设置**，
   在 **包含的进程列表（Process inclusion list）** 中追加一行 `dwm.exe` 并保存，保留已有条目。
3. 搜索并安装 **DWM Custom Projection Border**，在模组设置中开启
   **Disable border（关闭边框）** 并保存。
4. 在 Piik 中停止后重新开始分享，检查黄框是否消失。

恢复原状时，禁用该模组并重新开始分享。如果 `dwm.exe` 这一项是专门为该模组添加的，
也可以移除。若桌面出现异常，或 Windows 更新后不再兼容，先禁用模组。

最新操作说明见[模组作者说明](https://github.com/ramensoftware/windhawk-mods/blob/main/mods/dwm-custom-projection-border.wh.cpp)
和 [Windhawk 进程设置文档](https://github.com/ramensoftware/windhawk/wiki/Injection-targets-and-critical-system-processes)（英文）。

### 全屏或休眠后播放异常

- **播控按钮隐藏了：** 轻点对应画面即可重新呼出；使用这一路画面的控件，而不是另一张分享卡片。
- **没有全屏按钮或点击失败：** 将邀请链接复制到独立浏览器打开，例如安卓 Chrome 或
  iPhone Safari，避免使用聊天软件的内置浏览器。不支持系统全屏时，可用 **剧场模式** 放大网页内的画面。
- **全屏后 Piik 播控不见了：** 浏览器进入了自带的视频播放器。退出全屏、改用 **剧场模式**，
  即可保留 Piik 播控、弹幕和远控操作。
- **手机全屏仍有黑边：** 画面默认保持原始比例，可尝试横屏，或用播控上的 **切换画面适配**
  切换 **等比铺满** 或 **拉伸铺满**。如果已进入浏览器自带的视频播放器，先退出全屏再使用
  Piik 的画面适配。见[观看操作](./getting-started.zh-CN.md#加入朋友的房间)。
- **休眠或挂起后分享中断：** 唤醒设备，回到分享标签页，必要时重新开始分享。
  浏览器或系统挂起可能中断采集和播放。

## 声音与浏览器权限

[来源声音](#有画面但没有来源声音) · [房间语音](#听不到说话声) ·
[回声 / 多余声音](#回声或传出了多余的应用声音) · [麦克风 / 远控权限](#无法使用麦克风或远程控制)

### 有画面但没有来源声音

1. 取消视频静音，并检查播放音量。
2. 分享者应选择支持分享声音的来源，并在选源器中打开声音；可用声音取决于来源和平台。
3. 摄像头画面与麦克风输入分别选择。内置麦克风或 OBS 音频的用法，见[摄像头与音频输入](./sharing.zh-CN.md#摄像头与虚拟音频输入)。

### 听不到说话声

如果分享者使用 **分享麦克风**，先检查画面的[来源声音](#有画面但没有来源声音)，
并让分享者检查 **画质与声音 → 声音**。房间语音则按以下步骤排查：

1. 双方在同一房间点击 **加入语音**；旁边的箭头可选择 **只收听，不开麦**，主按钮会请求使用麦克风。语音房间选择框应指向你正在排查的房间。
2. 发言者检查浏览器的麦克风权限，以及 **语音设置** 中的输入设备和音量。
   使用麦克风需要 HTTPS 或 `localhost`。
3. 检查自己是否暂停收听或将对方本地静音。这些控制与视频静音分开；**暂停收听** 不会关闭自己的麦克风。

语音提示连接失败时，对照 [WebRTC 设置](./network.zh-CN.md#浏览器限制了-webrtc)及另一网络。
控件的使用方法见[房间语音](./room-tools.zh-CN.md#房间语音)。

### 回声或传出了多余的应用声音

扬声器被麦克风再次收音时，可使用耳机。Windows App 屏幕采集支持
[排除语音软件的来源音频](./sharing.zh-CN.md#分享屏幕时排除语音软件的声音)，但不会消除声学回声。

虚拟麦克风在 Piik 闭麦后仍可听见时，暂时关闭 **系统声音** 对照。如果声音消失，
说明混音软件的播放输出也进入了来源音频。检查其播放／监听路由，或只分享需要的应用窗口音频。
Piik 的麦克风静音不会关闭这条独立来源。

### 无法使用麦克风或远程控制

1. 打开当前 App 生成的完整 HTTPS 邀请。本地邀请应先[确认证书](#本地-https-证书提示)。
   普通 HTTP 内网页面可以观看、聊天和加入语音收听，但不能使用需要安全上下文的麦克风、摄像头采集和远控接口。
   仅修改链接里的协议名不会开启 HTTPS；`localhost` 只代表当前设备。
2. 麦克风不可用时，检查当前站点的浏览器权限和所选输入设备。
3. 远控需更新分享者 App 和站点，再刷新观众页面。分享者必须使用桌面 App 窗口／屏幕采集并开启远控；
   浏览器与摄像头采集不能接收远程输入。安卓可以分享屏幕，也可以作为观众控制电脑，但不能作为被控手机，
   因此安卓分享者页面没有开启远控的入口。随后按[授权步骤](./room-tools.zh-CN.md#让朋友操作共享的电脑)操作。

浏览器不接受本地证书例外时，改用可访问的 **公网邀请** 或具有可信证书的 HTTPS 站点。

## 手柄

### 手柄没有响应

1. 分享者通过 App 分享窗口或屏幕，并开启 **远程控制**。
2. 按[支持的平台与手柄设置](./remote-control.zh-CN.md#手柄)检查分享者端。
   外部驱动由分享者从官方渠道安装，Piik 不附带 SDK 或驱动；安装后重新开启远程控制。
3. 观众连接标准布局手柄并按一下按钮，让浏览器识别；取得远程控制权后，Piik 自动使用
   浏览器标准映射下的第一个已连接手柄。保持观看页面在前台，在游戏中加入对应玩家；
   手柄位已满时，断开不使用的手柄或结束该观众的远程控制。

观众只需使用浏览器，驱动检查与安装在分享者电脑完成。

## 反馈问题

请附上 Piik 版本、系统与浏览器、发生时间、预期结果和复现步骤。
采集问题还需说明来源类型、编码、显卡／驱动，以及其他来源或 VP8 是否正常；网络问题说明所用网络类型。

- **网页：** 打开页头的 **帮助**，开启 **诊断**。这会重新加载页面并中断当前活动；复现一次后，回到 **帮助 → 网页报告**，再进行其他刷新。
- **App 采集、托管或远控：** 先在 App 本机启动页打开 **帮助 → 诊断**，复现后点击 **帮助 → App 报告**。窄屏时从 **更多选项** 找到这些控件。
- **房间或连接失败：** 收集房间托管端与受影响参与者同一次尝试的报告；Server 托管时，请管理员保留对应服务错误。

报告保存在本机，分享前检查私人信息；[App 诊断说明](../../prototype/channel-server/README.md#app-diagnostics)
介绍报告范围。无法收集时，请提供完整的页面错误与复现步骤。

其他指南可在[文档中心](./README.zh-CN.md)找到。
